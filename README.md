# Web Audio AR Chess

## Опис проєкту

**Web Audio AR Chess** — це вебзастосунок для розпізнавання ArUco-маркерів за допомогою камери смартфона.

Програма працює без встановлення додаткового програмного забезпечення на смартфоні та запускається безпосередньо у веббраузері.

Основна ідея проєкту — створення універсальної платформи для настільних ігор із підтримкою:

- доповненої реальності (**Augmented Reality, AR**);
- комп'ютерного зору (**Computer Vision**);
- просторового позиціонування ігрових об'єктів;
- аудіосупроводу ігрових подій (**Audio Augmented Reality**).

На поточному етапі реалізовано базовий AR-конвеєр:

- отримання відеопотоку з камери смартфона;
- обробка кадрів;
- інтеграція OpenCV.js;
- розпізнавання ArUco-маркерів;
- візуалізація знайдених маркерів.

Для розпізнавання використовується словник:

```
DICT_4X4_1000
```

# Принцип роботи системи

## 1. Отримання відеопотоку

Модуль:

```
CameraManager
```

відповідає за:

- доступ до камери смартфона;
- запуск WebRTC `getUserMedia`;
- передачу відеопотоку у HTML-елемент:

```html
<video>
```

---

## 2. Формування кадру

Модуль:

```
FrameProvider
```

отримує поточний кадр із відеопотоку.

Результатом є об'єкт:

```
Frame
```

який містить:

- `imageData`;
- ширину кадру;
- висоту кадру;
- часову мітку.

---

## 3. Конвертація у формат OpenCV

Модуль:

```
OpenCvFrameConverter
```

виконує перетворення:

```
Frame
   ↓
cv.Mat
```

Формат кадру:

```
RGBA
```

перетворюється у формат, необхідний для комп'ютерного зору:

```
GRAY
```

---

## 4. Розпізнавання ArUco

Модуль:

```
OpenCvArucoDetector
```

використовує OpenCV.js:

```
aruco_ArucoDetector
```

Параметри:

```
Dictionary:
DICT_4X4_1000
```

Результатом детекції є:

- координати кутів маркера;
- ID маркера;
- список відхилених кандидатів.

---

## 5. Візуалізація результатів

Модуль:

```
Renderer
```

відображає:

- відеопотік;
- контури знайдених маркерів.

Поточний результат:

- зелений контур навколо кожного знайденого ArUco-маркера.

# Основні програмні модулі

Під час розробки використовуються:

## Модульність

Кожен компонент має власну відповідальність:

```
Camera
   |
Frame
   |
Detector
   |
Renderer
```

---

## Single Responsibility Principle

Кожен клас виконує одну задачу:

- камера не знає про детекцію;
- детектор не знає про відображення;
- Renderer не знає про OpenCV.

---

## Незалежність від бібліотеки

Інтерфейс:

```
ArucoDetector
```

дозволяє у майбутньому замінити реалізацію:

- OpenCV.js;
- js-aruco;
- власний алгоритм.
