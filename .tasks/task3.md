# Алгоритм компенсації перспективного зміщення ArUco-маркерів шахових фігур
# з використанням відомої висоти розташування маркера

---

# 1. Мета алгоритму

Метою алгоритму є визначення правильного положення шахової фігури на площині шахової дошки незалежно від її розташування на дошці.

Алгоритм компенсує перспективне зміщення ArUco-маркера, який знаходиться не на площині дошки, а над нею.

Основна причина зміщення:

- камера проектує всі точки на площину зображення;
- ArUco-маркер фігури знаходиться вище площини дошки;
- при перерахунку координат через гомографію виникає зміщення відносно реального положення основи фігури.

---

# 2. Особливість нового підходу

Попередній алгоритм визначав висоту маркера автоматично:


розмір маркера після гомографії
|
v
оцінка висоти h
|
v
компенсація


Такий підхід нестабільний через:

- оптичну дисторсію камери;
- залежність розміру маркера від положення у кадрі;
- похибку гомографії для об'єктів, які знаходяться над площиною дошки.

Новий алгоритм використовує відому фізичну висоту:


ID маркера
|
v
objects.json
|
v
marker_height
|
v
компенсація зміщення


---

# 3. Вхідні параметри алгоритму

## 3.1. Висота камери

Відстань від камери до площини дошки:


H (мм)


Наприклад:


H = 330 мм


---

## 3.2. Розмір шахової дошки

Фізичний розмір всієї дошки:


BoardSize (мм)


Наприклад:


BoardSize = 195 мм


---

## 3.3. Розмір клітинки

Оскільки дошка має 8x8 клітинок:


CellSize = BoardSize / 8


Приклад:


CellSize = 195 / 8

CellSize = 24.375 мм


---

## 3.4. Висота розташування ArUco-маркера

Для кожної шахової фігури відома висота:


marker_height (мм)


Це не висота всієї фігури.

Визначається саме висота центру ArUco-маркера:

         ArUco
          □
          |
          |
      h = marker_height
          |
          |
    поверхня дошки

---

# 4. Опис шахових фігур

Інформація зберігається у файлі:


objects.json


Приклад:

```json
[
    {
        "obj_id": 1,
        "marker_id": 163,
        "name": "біла тура",
        "audio_name": "tura.mp3",
        "color": "white",
        "marker_height": 70
    }
]

Поля:

marker_id
    |
    унікальний ID ArUco

marker_height
    |
    висота центру маркера над дошкою
5. Виявлення ArUco-маркерів

Для кожного кадру:

Camera frame
        |
        v
OpenCV ArUco Detector

визначає:

ID маркера;
чотири кути маркера;
центр маркера.

Для одного маркера:

P0 -------- P1


P3 -------- P2
6. Визначення площини шахової дошки

На дошці розміщено чотири кутових ArUco-маркери.

За ними визначаються:

TopLeft
TopRight
BottomRight
BottomLeft

Будується гомографія:

Image coordinates
        |
        |
        v
Board coordinates

Тобто:

pixel
  |
  v
millimeter on board
7. Перетворення маркера фігури у координати дошки

Для кожного маркера фігури:

беруться його кути:

P0
P1
P2
P3

і переводяться через гомографію:

pixel coordinates
        |
        v
board coordinates

Отримуємо:

B0
B1
B2
B3

у міліметрах.

8. Визначення центру маркера

Центр маркера:

CenterMarker

обчислюється:

CenterMarker =
(B0+B1+B2+B3)/4

Наприклад:

CenterMarker:

x = 145 мм
y = 82 мм
9. Визначення центру дошки

Центр дошки:

CenterBoard

визначається:

CenterBoard.x = BoardSize / 2

CenterBoard.y = BoardSize / 2

Для:

BoardSize = 195 мм

отримуємо:

CenterBoard:

x = 97.5 мм
y = 97.5 мм
10. Визначення напрямку перспективного зміщення

Обчислюється вектор:

V = CenterMarker - CenterBoard

Він показує напрямок, у якому маркер зміщується через висоту.

Приклад:

CenterMarker:

(145,82)


CenterBoard:

(97.5,97.5)

Тоді:

V:

x = 47.5 мм
y = -15.5 мм
11. Отримання висоти маркера

За ID маркера виконується пошук у:

objects.json

Приклад:

marker_id = 163

знаходиться:

marker_height = 70 мм
12. Розрахунок коефіцієнта компенсації

Коефіцієнт перспективного зміщення:

alpha = h / H

де:

h
-
висота маркера


H
-
висота камери

Приклад:

h = 70 мм

H = 330 мм

отримуємо:

alpha = 70 / 330

alpha = 0.212
13. Розрахунок компенсаційного вектора

Величина зміщення:

Correction = V * alpha

або:

dx = V.x * alpha

dy = V.y * alpha

Приклад:

dx = 47.5 * 0.212

dx = 10.1 мм


dy = -15.5 * 0.212

dy = -3.3 мм
14. Отримання скоригованого положення

Правильне положення фігури:

CorrectedCenter =
CenterMarker - Correction

або:

Corrected.x =
CenterMarker.x - dx


Corrected.y =
CenterMarker.y - dy

Саме:

CorrectedCenter

використовується для визначення клітинки.

15. Визначення координат клітинки

Розмір клітинки:

CellSize = BoardSize / 8

Координати:

column =
CorrectedCenter.x / CellSize


row =
CorrectedCenter.y / CellSize
16. Перевірка правильності розташування

Перевіряється:

чи знаходиться фігура у межах клітинки;
чи не виходить за межі;
чи відповідає очікуваному положенню.

Для перевірки використовується:

CorrectedCenter

а не:

CenterMarker

18. Що видаляється

Більше не використовується:

Spiece

та формула:

h = H * (1 - MarkerSize / Spiece)

Причина:

нестабільність біля країв кадру;
вплив дисторсії;
похибка оцінки висоти.
19. Переваги нового алгоритму

Переваги:

стабільна компенсація;
однакова точність у центрі та на краях дошки;
не залежить від розміру маркера після гомографії;
підтримка різних типів шахових фігур;
проста інтеграція через objects.json.
20. Обмеження

Алгоритм передбачає:

камера нерухома;
камера приблизно паралельна дошці;
висота маркера відома;
маркер жорстко закріплений на фігурі;
всі координати переведені у систему координат дошки.
